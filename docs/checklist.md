## Приоритетный чек-лист
Приоритизируются в соответствии с градацией: critical, high, medium, minor.

1. (Critical) Основные пользовательские пути, пользовательские данные, безопасность
   - Позитивный путь (хэппи-паз) бронирования: все поля заполненны корректно, дата и время в будущем, 3 кейса для позитивной проверки каждой переговорной
   - XSS-инъекция (+ sql-инъекция, если бы был бэк) - проверка каждого поля, где возможен ввод
   - Проверка обязательности полей (нельзя забронировать переговорную, не указав значение в обязательном поле)
	
2. (High) Проверки ожидаемых пользовательских путей, ключевая бизнес-логика, ограничения
	- Поле "Дата" (проверка невозможности ввода даты в прошлом)
	- Поле "Начало" (не может быть в прошлом для текущего дня, не может быть позже времени окончания)
	- Поле "Окончание" (не может быть в прошлом для текущего дня, не может быть раньше времени окончания)
	- Длительность бронирования (не меньше 30 минут, не больше 4 часов)
	- Поле "Участники" (ошибка при вводе числа меньше 0 и больше 20, валидация на количество участников работает в зависимости от выбранной переговорной - для малой ошибка от 5 участников, для средней - от 11 участников, для большой - от 20 участников)
	- Поле "Ваше имя" (проверка ввода имени из нескольких слов, на кириллице, на латинице, с спецсимволами в имени - дефисы/апострофы)
	- Поле "Рабочая почта" (валидная почта на кириллице, ошибка при неверном формате)
	- Проверка работы с контролами в полях (пролистывание списков времени, даты, увеличение/уменьшение количества участников)
	
3. (Medium) Негативные проверки, нефункциональные проверки
	- Невалидный ввод в поля даты, начала, окончания и участников (с клавиатуры, драг-энд-дропом, вставкой из буфера обмена)
		- Только пробелы
		- Буквы (кириллица/латиница)
		- Спец-символы, эмодзи
		- Отрицательные числа
		- Дробные числа
	- Проверка ограничений на максимальное количество символов в полях
	- Кроссбраузерное тестирование (Chrome, Safari и Firefox, + при необходимости учитывать ОС)
	- Мобильная верстка
	- Проверка орфографии и пунктуации в текстах
	- Проверка верстки на соответствие макетам дизайна
	- Проверка производительности (отсутствие утечек памяти)
	- Проверка удобства использования (кликабельность полей и контролов, скроллинг, размер текста)
	
4. (Minor)
	- Адаптивность при изменении размера окна браузера
	- Проверка исчезновения сообщений об ошибках при изменении полей
